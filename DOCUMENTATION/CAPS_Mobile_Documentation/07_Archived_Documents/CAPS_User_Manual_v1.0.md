# CAPS User Manual

Archived version: v1.0  
Current file: `../06_User_Manuals/CAPS_User_Manual_v2.0.13.pdf`

## Purpose
This archived manual records the early user guide structure for the CAPS mobile application before the current `v2.0.13` PDF user manual was finalized.

## Introduction
CAPS Mobile provides access to academic and support features through a mobile application. Available features depend on the user's role in the system.

## Getting started

1. Open the CAPS mobile app.
2. Enter the registered email and password.
3. Tap login.
4. Wait for the app to load the dashboard assigned to the user's role.

## Main user roles

| Role | Main access |
| --- | --- |
| Student | Dashboard, classes, leaderboard, results, and support |
| Faculty | Dashboard, class-related records, student information, and support |
| Program Chair | Users, subjects, classes, reports, and insights |
| Dean | Users, subjects, classes, analytics, reports, and support |
| Associate Dean | Administrative academic views and role-based management features |

## Student guide

Students can use the mobile app to:

- View their dashboard.
- Access assigned classes.
- Check leaderboard or academic progress features when available.
- Submit support concerns through the Help Center.

## Faculty guide

Faculty users can use the mobile app to:

- View assigned academic information.
- Access class-related records.
- Review student-related data where permitted.
- Use support features when needed.

## Administrator guide

Program chairs, deans, and associate deans can use the mobile app to:

- View role-based dashboards.
- Review users, classes, subjects, reports, or analytics.
- Access support-related records depending on permission level.

## Support and issue reporting

Users can submit concerns through the Help Center or support workflow. Reports should include a clear description of the issue and the affected feature.

## Earlier limitations

- The first manual version summarized workflows without detailed screenshots.
- Some role-specific screens were grouped together instead of documented separately.
- Advanced analytics and reporting instructions were still limited.
- The final PDF layout and version numbering were not yet applied.
