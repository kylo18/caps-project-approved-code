# Issue Reporting Guide

Archived version: v1.0  
Original location: `../02_Technical_Documentation/Issue Reporting Guide.md`

## Purpose
This early version documented how users could report issues in CAPS Mobile.

## Initial issue reporting flow
1. User opens the Help Center or support form.
2. User chooses an issue category.
3. User writes a short description.
4. User submits the issue report.
5. Admin reviews the submitted concern.

## Early issue categories
- Technical.
- Account.
- Academic.
- General.
- Other.

## Earlier limitations
- Admin handling steps were not yet fully explained.
- Ticket normalization was not yet documented.
- Review status and support workflow details were not yet complete.

## Version control note
This archived version shows the first documented issue reporting process before later revisions.
