# Dark Mode Implementation: Subject Models
## Summary of Changes
The mobile subject selection modal (accessed via the "Subjects" button on the Bottom Navigation bar for Faculty, Program Chairs, and Deans) was missing dark mode colors. The UI was originally hardcoded with light-mode backgrounds (`bg-white`) and text colors (`text-gray-700`), making it blindingly bright and difficult to read when the rest of the application was in dark mode.

We updated three separate files to fix this:
1. `src/components/subjectsDean.jsx`
2. `src/components/subjectsProgramChair.jsx`
3. `src/components/subjectsFaculty.jsx`

*Note: Students (role_id === 1) do not have this button on their Bottom Navigation, so no corresponding student modal needed changing.*

---

## Detailed Line-by-Line Changes (Example from `subjectsProgramChair.jsx`)

Here is exactly what we added to enable Tailwind's dark mode classes (`dark:`) while retaining the existing light mode aesthetics.

### 1. Main Modal Container Background
**Before:**
```jsx
className={`subject-selector-theme open-sans sm:bg-opacity-0 flex flex-col border-gray-300 bg-white transition-all duration-200 ease-in-out ...`}
```
**After:** Added `dark:bg-black` and `dark:border-white/10`.
```jsx
className={`subject-selector-theme open-sans sm:bg-opacity-0 flex flex-col border-gray-300 dark:border-white/10 bg-white transition-all duration-200 ease-in-out dark:bg-black ...`}
```

### 2. Dropdown Menus (Year Level & Program Filter)
**Before:**
```jsx
<ul className="animate-dropdown animate-fadein absolute left-0 z-10 mx-2 mt-1 w-[calc(100%-16px)] rounded border border-gray-300 bg-white p-1 shadow-lg">
```
**After:** Added `dark:bg-[#1a1a1a]` (a dark, slightly elevated gray) and `dark:border-white/10`.
```jsx
<ul className="animate-dropdown animate-fadein absolute left-0 z-10 mx-2 mt-1 w-[calc(100%-16px)] rounded border border-gray-300 bg-white dark:border-white/10 dark:bg-[#1a1a1a] p-1 shadow-lg">
```

### 3. List Item Hover States
**Before:**
```jsx
<li className="flex cursor-pointer items-center gap-2 px-2 py-2 text-sm hover:bg-orange-50" ...
```
**After:** Added dark mode text (`dark:text-gray-200`) and a subtle white overlay on hover (`dark:hover:bg-white/5`).
```jsx
<li className="flex cursor-pointer items-center gap-2 px-2 py-2 text-sm hover:bg-orange-50 dark:hover:bg-white/5 dark:text-gray-200" ...
```

### 4. Search Input Box
**Before:**
```jsx
<input className="w-full rounded-md bg-gray-100 py-2 pr-10 pl-10 text-[13px] font-semibold text-gray-700 outline-none hover:bg-gray-200" ...
```
**After:** Lowered the background opacity for the search field in dark mode and lightened the text. 
```jsx
<input className="w-full rounded-md bg-gray-100 py-2 pr-10 pl-10 text-[13px] font-semibold text-gray-700 outline-none hover:bg-gray-200 dark:bg-white/5 dark:text-gray-200 dark:hover:bg-white/10" ...
```

### 5. Horizontal Dividers
**Before:**
```jsx
<div className="mt-2 mb-1 h-[0.5px] bg-[rgb(230,230,230)]" />
```
**After:** Used a subtle white opacity for dark mode boundaries.
```jsx
<div className="mt-2 mb-1 h-[0.5px] bg-[rgb(230,230,230)] dark:bg-white/10" />
```

## Technical Learnings
- **The `dark:` Prefix:** Tailwind uses the `dark:` prefix to apply utility classes only when a specific `<html className="dark">` state is toggled on (or based on OS preference).
- **Subtle Dark Elevation:** Instead of using pure `dark:bg-gray-800` to represent floating menus (like dropdowns or Kebab menus), we used `dark:bg-[#1a1a1a]` with `shadow-lg` to create a smooth, premium dark theme that doesn't feel aggressively black. 
- **Borders:** In dark mode, harsh borders like `border-gray-600` can look noisy. We used `dark:border-white/10` to create a smooth, transparent 10% white border that looks polished on dark backgrounds.
- **Component Code Duplication:** We noticed that `subjectsDean.jsx`, `subjectsProgramChair.jsx`, and `subjectsFaculty.jsx` share 95% of their dropdown logic. If you continue developing this app, creating a generic reusable `SubjectModal.jsx` component that accepts the `fetchSubjects` logic via props would significantly reduce maintenance overhead!
